# 04 — Визуальный стиль: уровень AB2 / Friends 2020 процедурно на Canvas 2D

Спецификация для рендера браузерного клона: TypeScript + Vite, planck.js 1.5.x, Canvas 2D, процедурные спрайты в кэше offscreen-холстов, DOM-UI, Web Audio. Мир в метрах, ось Y вверх, шаг 1/60 с.
Ассеты Rovio не используем. Всё ниже рисуется кодом: стиль узнаваемый, исполнение своё.

Легенда пометок:
- **[замер]** — проверено прототипом `docs/research/04-visual-lab/` (Chromium headless, программный растеризатор SwiftShader, 1600×900, dpr 1). Тайминги — **верхняя граница**: на GPU-канвасе быстрее.
- **[факт]** — открытые источники (список в §14).
- **[рекомендация]** — точных данных об оригинале нет; значение подобрано и проверено на скриншотах прототипа.

Превью прототипа (всё нарисовано кодом из §11 и `04-visual-lab/visual.js`):
- `04-visual-themes.jpg` — 4 темы в виде рогатки (viewH 15 м);
- `04-visual-zoomout.jpg` — «Зелёные холмы» при общем плане (viewH 38 м);
- `04-visual-sheet.jpg` — материалы × формы × стадии повреждений, рогатка, TNT, облака, взрыв, «пуф» свиньи, обломки, перья, всплывающие очки, звёзды.

Связь с другими документами: 01-gameplay (рогатка, след, очки, камера, тряска), 02-characters (стиль персонажей, обводки, тени, кэш), 03-physics (размеры блоков, inset коллизий, пороги стадий, g = 15). Значения из них здесь не дублируются, а уточняются для отрисовки.

## 1. Арт-дирекция

### 1.1. Что берём из оригиналов

- **Classic / Friends (2009–2020)** [наблюдение]: плоская мультяшная заливка, толстые тёмные контуры, простые вертикальные градиенты, фон — несколько силуэтных слоёв (небо, облака, холмы, трава), материалы читаются по фактуре: волокна у дерева, блики у стекла, крапины у камня.
- **AB2 (2015+)** [факт: Rovio хотели показать, «как выглядела бы Angry Birds, сделанная в 2015-м»; обзоры отмечают «живые» фоны, ветер, обломки, летящие в камеру]: мягкий объём, контровой свет, глубина за счёт дымки, насыщенные эффекты разрушения.
- **Наша формула**: игровые объекты (птицы, свиньи, блоки, рогатка, рельеф) — с обводкой и объёмом. Фон — без обводок, с дымкой. Такое разделение даёт мгновенную читаемость: всё с контуром можно сломать или с этим взаимодействовать.

### 1.2. Правила (проверяемые)

| # | Правило | Число / проверка |
|---|---|---|
| R1 | Свет сверху-слева у всех объектов | блик в верхне-левой четверти, тень снизу-справа, рим-лайт по верхней кромке |
| R2 | Обводка — затемнённый цвет материала, не `#000` | L* обводки 20–45 (wood `#4A2810` L*20, stone `#30353C` L*22, ice `#246A9E` L*43) |
| R3 | Контраст объекта с фоном | ≥ 3:1 по яркости между фоном и **обводкой или заливкой** объекта. Пример: обводка свиньи `#1F4A0E` против ближних холмов `#66BF4B` — 4.46:1 [замер расчётом] |
| R4 | Насыщенность и контраст падают с глубиной | каждый следующий дальний слой смешивается с цветом дымки темы (`fog`) на +15–45 %: деревья 18 %, дальние холмы 30 % у подножия, горы 45 % у подножия |
| R5 | Фон светлее и мягче игрового плана | средняя L* фона на высоте сооружений ≥ 60 (день); блоки и свиньи — самые насыщенные пятна кадра |
| R6 | Скругления везде | углы блоков r = 7 % (дерево, лёд) / 14 % (камень) меньшей стороны; `lineJoin = 'round'`, `lineCap = 'round'` |
| R7 | Мин. толщина линии на экране | 1.5 px устройства для контуров, 1.2 px для деталей; детали < 1 px не рисуем (LOD) |
| R8 | Материал читается без цвета | дерево — волокна и гвозди; лёд — диагональные блики и полупрозрачность; камень — крапины и шумовая фактура. Важно для дальтоников |
| R9 | Эффекты ярче мира | вспышки и искры рисуются `'lighter'` поверх сцены; дым и пыль — полупрозрачные, без обводки |
| R10 | Никаких логотипов и надписей Rovio | надпись «TNT» на ящике — общее обозначение, допустимо |

- Ствол рогатки рисуется **до** рельефа. Тогда травяная кромка перекрывает его основание (оно уходит на 0.4 м под землю) и рогатка выглядит вкопанной.

## 3. Параллакс

### 3.1. Математика слоя

Обозначения: `W, H` — холст в пикселях устройства; `s = view.scale` — пикселей на метр мира; `camX, camY` — центр камеры, м; `AIM_VIEW_H = 15 м` (01 §6.2); `sRef = H / AIM_VIEW_H` — масштаб вида рогатки.

```ts
// Масштаб слоя: при f = 1 совпадает с миром, при f = 0 не зумится вовсе.
const sL = sRef * Math.pow(s / sRef, f);
// Экранные координаты точки слоя (xL, yL), где yL отсчитан от базы слоя baseY:
X = W / 2 + (xL - camX * f + drift * time) * sL;
Y = H / 2 - (yL + baseY - camY * fy) * sL;          // fy = f, если не задано иное
```

Следствия:
- При отъезде камеры (viewH 15 → 42 м, `s/sRef = 0.357`) масштаб гор падает лишь до ×0.88, ближних холмов — до ×0.66, деревьев — до ×0.53. Небо и горы остаются «большими», мир уменьшается. Так выглядит общий план AB [замер, `04-visual-zoomout.jpg`].
- При подъёме камеры (`camY` растёт) база слоя опускается на `camY·fy·sL`, то есть дальние слои уходят вниз медленнее мира. Небо открывается вверх.
- Тряска камеры (01 §6.4) прибавляется к `camX/camY` **до** расчёта слоёв, поэтому дальние слои автоматически трясутся в `f` раз слабее.
- Каждый слой ниже своей базы заливается сплошным цветом до низа экрана (`fillBelow`), поэтому щелей между слоями не бывает при любом зуме.

### 3.3. Кэш полос (strip)

```ts
// Полоса = один период слоя, отрисованный в offscreen-холст.
const bucket = 2 ** (Math.round(4 * Math.log2(sL)) / 4);         // шаг ×1.19
const ppm = Math.min(bucket * layer.res, 4096 / layer.period);     // ≤ 4096 px по ширине
key = `${theme}:${layer.id}:${bucket.toFixed(3)}`;
// Отрисовка: drawImage(strip, x, yTop, strip.width·k, strip.height·k), k = sL / ppm
```

- Пока `k ∈ [0.75, 1.4]`, старую полосу просто масштабируем. Новую строим, когда зум не меняется 0.25 с, и не больше одной полосы за кадр. Построение полосы занимает 5–20 мс [замер: первый кадр всего фона 42–59 мс], поэтому делать его посреди твина камеры нельзя.
- При `f ≤ 0.25` во всём диапазоне зума хватает **одной** полосы (×0.88…×0.77). Перестраиваются только ближние холмы (2 ступени) и деревья (3–4 ступени).
- Разрешение `res < 1` у дальних слоёв экономит память и даёт мягкость, похожую на глубину резкости.
- Память при dpr 2 (sRef 144 px/м): горы 4096×576 ≈ 9.4 МБ, дальние холмы ≈ 7.2 МБ, ближние ≈ 8.2 МБ; итого ~25 МБ. При dpr 1 — около 7 МБ.
- Облака и деревья в игре лучше держать **отдельными спрайтами**: 4 варианта облака и 4–5 вариантов дерева на тему, примерно 8–12 `drawImage` на слой. Полоса деревьев 30 м при dpr 2 весила бы ~25 МБ. В прототипе всё сделано полосами, визуально разницы нет.
- Тёплый кадр фона и рельефа (полосы готовы) занимает **0.4–1.1 мс** [замер].

## 5. Фон: рецепты слоёв

### 5.1. Небо и солнце

- Небо — `createLinearGradient(0, 0, 0, H)` со стопами темы, заливка всего экрана. Градиент создаётся заново только на `resize`. Дешёвая альтернатива: холст 1×H, растянутый `drawImage`.
- Солнце: позиция `(x·W − camX·0.02·sRef, y·H + camY·0.02·sRef)`. Ореол — запечённый радиальный спрайт 256×256 (цвет `glow`: α `glowA` в 0, 0 в 1), рисуется размером `9R × 9R`. Диск — радиальный градиент со смещённым на (−0.3R, −0.3R) центром: белый → `core`.

### 5.2. Облако (спрайт)

Параметры: ширина `w` = 3–7 м, высота `h = 0.42 w`, плоское дно на `base = 0.78 h`.

1. 5–7 кругов: `t_i = (i + 0.5)/n`, `x_i = w·(0.12 + 0.76·t_i)`, `r_i = h·(0.28 + 0.34·sin(π t_i))·U(0.85, 1.15)`, центр `y_i = base − 0.55 r_i`. Плюс прямоугольник `[0.1w, 0.9w] × [base − 0.25h, base]` — сплошное «брюхо».
2. Клип `y < base` (плоское дно). Объединение кругов (одна `Path2D`, правило nonzero) заливается вертикальным градиентом: `top` на 0…0.55, `bottom` на `base`.
3. В клипе облака: тени — круги `(x + 0.25r, y + 0.45r)`, радиус `0.8r`, цвет `bottom` α 0.55. Блики — круги `(x − 0.3r, y − 0.35r)`, радиус `0.45r`, белый α 0.55.
4. Обводки нет. Альфа слоя — `cloud.alpha`.

Код — §11.2.

### 5.3. Горы (гребенчатый силуэт)

- Теневые склоны: склоны, где `H` убывает вправо (смотрят от света), — клин между гребнем и его копией, сдвинутой на `(−0.55·Δh, −0.9·Δh)`, где `Δh` — перепад от вершины. Цвет `shade`, α 0.5.
- Снег (`snow`): выше `snowY = 0.62·maxH`, нижний край волнистый: `snowY + 0.35·sin(2.3x) + 0.25·sin(5.1x + 1)`.

## 6. Рельеф (`drawTerrain`)

Рельеф статичен, поэтому вся геометрия строится **один раз на уровень** в метрах (`Path2D`), а каждый кадр рисуется в мировой трансформации. Это 6–8 fill/stroke на полигон, стоимость пренебрежимая.

### 6.1. Грунт (`kind: 'ground'`)

1. **Текстура** — бесшовный тайл: 512×512 px на 4 м при HIGH, 256 px при LOW.
   - Фон: fBm шум (3 октавы, 8 клеток), цвет `lerp(soil, soilDark, clamp((v − 0.35)·2.2, 0, 1))`.
   - Камушки: 28 на тайл (≈1.75/м²). Эллипс с полуосями `rx = 0.06–0.17 м`, `ry = rx·U(0.55, 0.8)`, случайный поворот. Ободок `pebbleDark` +1.5 px, тело `pebble`, блик — эллипс `(−0.3rx, −0.35ry)`, полуоси `0.4rx × 0.3ry`, белый α 0.35. Камушки у края тайла рисуются 9 раз со сдвигами ±size — так тайл остаётся бесшовным.
2. **Заливка**: `createPattern(tile, 'repeat')` + `pattern.setTransform(new DOMMatrix().scale(4/size, −4/size))`. Паттерн задан в мировых единицах (метры, флип Y) и «прилипает» к миру при панорамировании.
3. **Глубина**: поверх — линейный градиент `soilDeep` от α 0 на `maxY` полигона до α 0.75 на `maxY − 5 м`.
4. **Кромка** вдоль верхних рёбер. Ребро верхнее, если внешняя нормаль `ny > 0.45`, то есть уклон < 63°.
   - Полоса толщиной 0.34 м вдоль ребра. Нижний край фестончатый: точки через 0.22 м, у каждой второй толщина +0.09 м.
   - «Губа» тени: та же полоса, сдвинутая на −0.06 м по Y, цвет `lip`.
   - Полоса: градиент `top` (на кромке) → `dark` (на глубине 0.44 м).
   - Блик: линия на 0.06 м ниже кромки, `lineWidth 0.07`, цвет `light`, `lineCap round`.
5. **Обводка** полигона: `lineWidth = max(0.06, 1.5/scale)`, цвет `outline`, `lineJoin round`.
6. **Поверх обводки**:
   - `blades: 'grass'`: травинки-треугольники с основанием 0.07 м, высотой 0.07–0.17 м, шагом 0.09–0.2 м, наклоном ±0.04 м, цветом `dark`. Все травинки — одна `Path2D`, один `fill`.
   - `'lumps'` (снег): полукруги r 0.06–0.12 м через 0.3–0.6 м цветом `top`.
   - `'none'` (песок): ничего. Ракушки уже в тайле.

### 6.2. Скалы и помосты

- `rock`: вертикальный градиент `light` → `dark` по bbox полигона. Трещины: 1 на ~1 м² (не меньше 4) — ломаная из 3 сегментов вниз, длина сегмента до 0.5 м, `lineWidth 0.05`, цвет `outline` α 0.45. Обводка `outline` 0.06 м. Для `meadow` [рекомендация]: мох — полоса 0.12 м цвета `#6FAE3A` по верхним рёбрам.
- `platform` (неразрушимый помост) [рекомендация]: каменная кладка. Заливка как у `rock`, швы «кирпичей» 1.0×0.5 м со смещением рядов на 0.5 м, шов `rock.dark` 0.03 м + светлая линия `rock.light` α 0.6 со сдвигом (+0.015, −0.015). Так помост отличается от разрушаемых блоков: у тех есть фаска и скруглённые углы.

## 7. Блоки, TNT и повреждения

### 7.1. Общий контракт спрайта

`renderBlock(material, shape, wM, hM, damageStage, seed, ppu): Sprite` (02 / спецификация).

- Холст: `(w + 2·pad)·ppu × (h + 2·pad)·ppu`, где `pad = OUT_BLOCK + 2/ppu`. Начало в центре bbox (`ox = W/2, oy = H/2`), спрайт-пространство Y вниз. Для `circle`: `w = h = диаметр`.
- Рисуется **визуальный** размер из `BlockDef`. Коллизия меньше на `INSET = 0.0075 м` с каждой стороны (03 §2.1 A6), так что блоки «встык» выглядят встык.
- Формы: `rect` — roundRect; `circle`; `triangle` — прямой угол внизу слева (в спрайт-пространстве вершины `(−w/2, +h/2)`, `(−w/2, −h/2)`, `(+w/2, +h/2)`); `isoTriangle` — основание внизу, вершина `(0, −h/2)`.
- Порядок: тело (клип по форме) → обводка `max(OUT_BLOCK, 1.5/ppu)`, цвет `outline` → трещины (клип по форме) → сколы (`destination-out`).
- Варианты: `seed & 3` — 4 варианта узора на размер, чтобы одинаковые балки не выглядели клонами и кэш не раздувался.
- Стоимость генерации: **0.17–0.52 мс** на спрайт при 72–144 ppu [замер].

### 7.3. Дерево

1. Скругление углов `clamp(0.07·mn, 0.012, 0.05)`. Вертикальный градиент: `light` (0) → `base` (0.35) → `dark` (1).
2. **Волокна** вдоль длинной оси:
   - число линий `n = max(2, round(thick/0.075))`, база `y0_i = −thick/2 + (i + 0.5)·thick/n ± 0.2·thick/n`;
   - каждая линия — синусоида `y = y0 + 0.012·sin(2πx/λ + φ)`, `λ = U(0.6, 1.3)`, шаг 0.04 м, `lineWidth U(0.008, 0.016)`, цвет `grain` α 0.55.
3. **Сучки**: `floor(len/0.9·U + U·0.8)` штук. Эллипс 0.05×0.025 цвета `knot` + кольцо 0.075×0.04 цвета `grain` α 0.7. Волокна обтекают сучок: `Δy = ±0.035·exp(−d²/0.01)·exp(−|y0 − ky|/0.08)`, где `d = x − kx`.
4. **Торцы** (если `len/thick > 2.2`):
   - затемнение 0.12 м от края, `deep` α 0.45 → 0;
   - гвозди в 0.09 м от торца: один по центру или два на ±0.25·thick, если `thick > 0.3`;
   - гвоздь: радиус `clamp(0.07·thick, 0.012, 0.022)`, тень `deep` (+0.25r, r·1.1), шляпка `nail`, блик белый α 0.6 (r·0.35 в (−0.3r, −0.3r)).
5. **Ящик** (если `mx/mn < 1.6` и `mn > 0.35`; это все квадраты 0.5 / 0.85 / 1.0 из 03):
   - рамка `f = 0.2·mn`, внутренняя панель `deep` α 0.5;
   - диагональная доска шириной `1.05·f` от левого нижнего угла к правому верхнему, градиент `light` → `base`, обводка 0.018;
   - контур панели — `outline`, 0.02.
6. **Доски** (иначе, если `mn > 0.3`; например колонна 0.5×2 и перекрытие 4×0.5 из 03): швы через `mn/round(mn/0.2)`, `deep` α 0.8, 0.016.
7. **Фаска** (только `rect`): `b = clamp(0.16·mn, 0.025, 0.07)`. Трапеции сверху и слева — `light` α 0.75, снизу и справа — `deep` α 0.55.
8. **Круг** — торец бревна:
   - сердцевина `light` r 0.82R со сдвигом (−0.05R, −0.05R);
   - 5 годичных колец r = 0.15k·R с волной 4 %·sin(3a + k), `grain` α 0.8;
   - кора — кольцо `deep` шириной 0.16R на радиусе 0.92R.

Код — §11.1.

### 7.4. Лёд / стекло

1. Заливка всего блока с `globalAlpha 0.86` (видно фон), диагональный градиент от верхнего левого угла к нижнему правому: `light` → `base` (0.45) → `dark`.
2. Фасетки:
   - светлый треугольник `(−w/2, −h/2)`, `(0.1w, −h/2)`, `(−w/2, 0.25h)`, белый α 0.22;
   - тёмный `(w/2, h/2)`, `(−0.15w, h/2)`, `(w/2, −0.2h)`, `deep` α 0.22.
3. Внутренняя рамка «стекла» (если `mn > 0.3`): отступ `0.16·mn`, белый α 0.55, 0.03.
4. Блики-полосы под −45°: широкая шириной `0.16·mn` в точке `−0.18·diag` (белый α 0.55) и узкая шириной `0.07·mn` на `+0.26·mn` правее (α 0.3).
5. Внутренний блик-уголок вдоль верхней и левой кромок: отступ `clamp(0.06mn, 0.015, 0.035)`, белый α 0.85, `lineWidth clamp(0.06mn, 0.012, 0.03)`. У круга — дуга от 1.05π до 1.55π.
6. Искорка: 4-лучевая звезда из 4 квадратичных кривых, центр `(−w/2 + 0.22mn, −h/2 + 0.22mn)`, размер `clamp(0.12mn, 0.03, 0.08)`, белая.

### 7.5. Камень

1. Скругление `clamp(0.14·mn, 0.02, 0.09)`. Вертикальный градиент: `light` → `base` (0.4) → `dark`.
2. **Шумовая фактура**: тайл 128 px = 1 м, fBm 4 октавы, 6 клеток. При `t = clamp((v − 0.5)·2.5, −1, 1)`:
   - `t > 0` → белый с α `t·0.27`;
   - иначе `rgb(20,24,30)` с α `−t·0.35`.

   Паттерн со случайным сдвигом на блок, `setTransform(translate(U·128, U·128).scale(1/128))`.
3. Крапины: `round(w·h·60)` точек r 0.006–0.016, пополам `deep` α 0.6 и `light` α 0.8.
4. Плиты (если `mx/mn > 2.2`): `max(1, round(mx/(1.6mn)) − 1)` поперечных швов. Шов — ломаная из 5 точек с дрожанием ±0.06mn, рисуется как трещина: `deep` α 0.9, 0.018 + светлая `light` α 0.9 со сдвигом 0.008.
5. Валун (`circle`): радиальный градиент из `(−0.18w, −0.2w)`: белый α 0.35 → 0 (0.6) → чёрный α 0.25 на краю.
6. Фаска `clamp(0.18·mn, 0.03, 0.09)`: `light` α 0.7, `deep` α 0.6.

### 7.6. Стадии повреждений

Стадия приходит в `EntityView.damageStage` (0…3). Пороги ядра: `hp/maxHp < 0.75 / 0.5 / 0.25` (03 §3.3). Событие `blockDamaged{stage}` → спрайт новой стадии, 2 облачка пыли и 2–3 мелких обломка (§8).

| Стадия | Дерево / камень | Лёд | Сколы углов |
|---|---|---|---|
| 0 | — | — | — |
| 1 | 1 главная трещина (+ветки) | паутина: 3 луча, длина ×0.35 | — |
| 2 | 3 трещины | 5 лучей ×0.75 + кольцо на 0.35 | 1 угол, размер ×0.8 |
| 3 | 6 трещин | 7 лучей ×1.2 + кольца 0.3 и 0.6 + выпавший осколок | 2 угла, размер ×1.3 |

**Генератор трещин** (детерминирован от `seed`; стадия n показывает первые k трещин, поэтому трещины копятся, а не прыгают):

- Старт на случайной кромке, направление — внутрь блока. Шаг `segLen·U(0.6, 1.4)`, на каждом шаге угол дрожит на ±`jitter`.
- Длина трещины `mn·U(0.5, 1.1) + mx·0.15·U`.
- Ветвление: вероятность `branchP` на шаг, только 1 уровень, угол ±(0.5…1.0) рад, длина ×0.4, толщина ×0.6. Ветка показывается вместе с родителем.
- Параметры:
  - дерево — `segLen 0.07`, `jitter 0.35`, `branchP 0.25`. [рекомендация] Тянуть угол к оси волокон на 30 % за шаг, чтобы дерево трескалось «вдоль»;
  - камень — `segLen 0.055`, `jitter 0.75` (рвано), `branchP 0.35`.
- Толщина: дерево `clamp(0.045mn + 0.012, 0.016, 0.034)`, камень `clamp(0.05mn + 0.014, 0.018, 0.04)`, сужение к концу до ×0.35.
- Отрисовка (гравировка при свете сверху-слева): сначала светлая линия (×0.55 толщины) со сдвигом (+0.45w, +0.45w) вниз-вправо — это освещённая стенка щели. Затем тёмная щель поверх.

**Паутина льда**:
- точка удара в пределах ±0.3·(w, h) от центра; 7 лучей под углами `(i + U·0.6)/7·2π`;
- луч — шаги по 0.06 м, угол дрожит на ±0.15 рад;
- кольца соединяют соседние лучи на доле длины через середину с дрожанием ±0.02;
- линия: подложка `crackDark` α 0.75 толщиной 1.8·lw, поверх белая 0.8·lw, где `lw = clamp(0.035mn + 0.008, 0.012, 0.026)`;
- в точке удара — белое пятно r 2.2·lw α 0.7;
- стадия 3: треугольник (удар, луч 1 на 0.6, луч 2 на 0.6) заливается `deep` α 0.45 — выпавший осколок.

**Скол угла** (не для `circle`):
- полигон из 5 точек у угла, размер `csz = clamp(0.22mn, 0.04, 0.16)·(0.8 | 1.3)`, стороны ×U(0.7, 1.2);
- приём без «дыр» в контуре: (1) обвести полигон скола линией `2·lw` цвета `outline` **в клипе формы блока**; (2) `destination-out` залить полигон.

В итоге по новой кромке скола остаётся обводка толщиной `lw`. Без клипа обводка вылезает за силуэт — ошибка была поймана в прототипе.

Физическая форма блока при этом не меняется. Скол — не больше 16 % меньшей стороны, так что несоответствие незаметно.

### 7.7. TNT

`renderTnt(size)`:

## 8. Эффекты (`Fx`)

### 8.1. Архитектура

- Пул частиц — структура массивов (`Float32Array`: x, y, vx, vy, ang, ω, size, life, maxLife, kind, color, flags), без аллокаций в кадре.
- Лимит: 500 / 350 / 250 (HIGH / MED / LOW); за кадр рождается не больше 120.
- При переполнении вытесняются самые старые частицы с наименьшим приоритетом: пыль 0 < осколки 1 < щепки и крошка 1 < перья 2 < элементы взрыва 3 < всплывающие очки (∞, отдельный список, не вытесняются).
- Интеграция — на кадровом `dt` (косметика, детерминизм не нужен):
  - `v *= exp(−drag·dt)`, `vy −= g·dt`, `x += vx·dt`, `ang += ω·dt`;
  - отскок от земли: `groundHeightAt(x)` — высоты верхних рёбер рельефа, сэмплированные через 0.25 м при загрузке уровня. При `y < h`: `vy = −vy·e`, `vx *= 0.6`, `ω *= 0.5`; после второго отскока частица лежит до затухания.
- Рисование частиц — **пачками по цвету**: один `beginPath`, много `arc`/полигонов, один `fill`. Вне экрана частицы не рисуются: проверка AABB с запасом 1 м.
- Источник случайности — `Math.random`. Эффекты не влияют на ядро.

### 8.6. Всплывающие очки

Цвета и обводки — 01 §9.3. Отрисовка в экранном пространстве с якорем в мире, без кэша: 10 надписей `strokeText + fillText` стоят 0.1 мс [замер].

```ts
const px = Math.max(14 * dpr, sizeM * view.scale) * popScale;   // sizeM: pig/bonus 0.9, block 0.6
ctx.font = `400 ${px}px "Luckiest Guy", "Rubik", sans-serif`;     // цифры; Rubik 900 — запасной вариант
ctx.textAlign = 'center'; ctx.textBaseline = 'middle'; ctx.lineJoin = 'round';
ctx.fillStyle = 'rgba(0,0,0,0.3)'; ctx.fillText(t, 0, px * 0.07);  // мягкая тень
ctx.lineWidth = px * 0.18; ctx.strokeStyle = stroke; ctx.strokeText(t, 0, 0);
const g = ctx.createLinearGradient(0, -px * 0.45, 0, px * 0.45);
g.addColorStop(0, mix(fill, '#FFFFFF', 0.45)); g.addColorStop(0.5, fill); g.addColorStop(1, mix(fill, '#000000', 0.12));
ctx.fillStyle = g; ctx.fillText(t, 0, 0);
```

Анимация (01): `popScale` 0.4 → 1.15 за 0.10 с → 1.0 за 0.08 с; подъём на 1.4 м за 0.9 с (`easeOutQuad`); с 0.6 с α 1 → 0 за 0.3 с. Перекрытие: новое число на расстоянии меньше 0.5 м от живого поднимается на +0.45 м по Y.

### 8.7. Звёзды (окно результатов и иконки уровней)

- Появление — по 01 §10. Искры: 8 четырёхлучевых звёздочек `#FFF7C0` в режиме `'lighter'`, радиальная скорость 2–4 R/с, жизнь 0.5 с.

### 8.8. Тряска камеры

Формула и амплитуды — 01 §6.4 (`A = min(0.35, impulse/400)`, затухание 0.3 с). Реализация:

```ts
// несколько одновременных тряск складываются, сумма ограничена 0.35 м
amp = Σ A_i · (1 − t_i/T_i)²;  amp = Math.min(amp, 0.35);
const n = (t: number, k: number) => 0.6 * Math.sin(2 * Math.PI * 7.3 * t + k) + 0.4 * Math.sin(2 * Math.PI * 13.1 * t + 1.7 * k);
camX += amp * n(time, 0); camY += amp * n(time, 2.1);   // до расчёта видов и слоёв
```

### 8.9. Контактные тени

По 02 §5.8 — только для птиц и свиней: эллипс `rgba(0,0,0,0.22)` под телом на высоте поверхности. У блоков теней нет: их контакт показывают обводка и фаска.

| `@fontsource/lilita-one` | 400 | **нет** | то же; в `package.json` уже есть — **убрать** или не использовать для текста |
| `@fontsource/bowlby-one`, `titan-one`, `bangers`, `chewy`, `paytone-one`, `fredoka`, `baloo-2` | — | нет | не подходят |
| **`@fontsource/rubik`** | 300–900 | **да** (cyrillic, cyrillic-ext) | **выбор**: 900 — плотный, мягкие углы, мультяшный «вес» как у AB-интерфейса; хорошо держит толстую обводку |
| `@fontsource/nunito` | 200–900 | да | круглее, но легче и «офиснее» при 900 |
| `@fontsource/m-plus-rounded-1c` | 100–900 | да | хорош, но пакет огромный (японские подмножества) |
| `@fontsource/balsamiq-sans` | 400, 700 | да | комиксный, но тонкий |
| `@fontsource/seymour-one`, `unbounded` | 400 / 200–900 | да | слишком широкие: длинные русские слова не влезают в кнопки |
| `@fontsource/oi`, `rubik-mono-one`, `russo-one`, `days-one`, `marmelad` | — | да | Oi нечитаем, Mono слишком разрежен, Russo/Days — «техно», Marmelad тонкий |

**Решение** [рекомендация]:
- основной шрифт — **Rubik 900** (заголовки, кнопки, HUD, «TNT»), **Rubik 700** (мелкий текст);
- акцентный — **Luckiest Guy 400**, только для строк из цифр и латиницы (всплывающие очки, счёт в HUD, номера уровней). Стек `"Luckiest Guy", "Rubik", sans-serif`.

Почему Rubik: из проверенных пакетов с кириллицей только у него вес 900 даёт плотный «мультяшный» силуэт и не разваливается под обводкой 0.18 em [замер: `fonts`-лист, 54 px]. Ширина строки «УРОВЕНЬ ПРОЙДЕН! 12 340» при 54 px — около 790 px против 775 у Nunito 900 и 975 у Unbounded 900. Мягкие углы глифов близки к «пухлому» стилю AB.

### 9.2. Подключение (только нужные подмножества)

Готовые CSS `@fontsource/rubik/900.css` тянут arabic/hebrew/latin-ext, а в сборке `build:single` всё инлайнится. Поэтому грузим файлы явно через FontFace API. Пакет экспортирует `./files/*.woff2`.

```ts

import luckyLat from '@fontsource/luckiest-guy/files/luckiest-guy-latin-400-normal.woff2?url';

const LAT = 'U+0000-00FF,U+0131,U+0152-0153,U+02BB-02BC,U+02C6,U+02DA,U+02DC,U+0304,U+0308,U+0329,U+2000-206F,U+20AC,U+2122,U+2191,U+2193,U+2212,U+2215,U+FEFF,U+FFFD';

export const FONT_UI = '"Rubik", system-ui, sans-serif';
export const FONT_NUM = '"Luckiest Guy", "Rubik", sans-serif';

export async function loadFonts(): Promise<void> {
  const faces = [
    new FontFace('Rubik', `url(${rubik900Lat})`, { weight: '900', unicodeRange: LAT, display: 'block' }),
    new FontFace('Rubik', `url(${rubik900Cyr})`, { weight: '900', unicodeRange: CYR, display: 'block' }),
    new FontFace('Rubik', `url(${rubik700Lat})`, { weight: '700', unicodeRange: LAT, display: 'block' }),
    new FontFace('Rubik', `url(${rubik700Cyr})`, { weight: '700', unicodeRange: CYR, display: 'block' }),
    new FontFace('Luckiest Guy', `url(${luckyLat})`, { weight: '400', display: 'block' }),

```

- Размер в сборке: Rubik 900 — 17.8 + 7.4 КБ, Rubik 700 — 19.1 + 7.9 КБ, Luckiest Guy — 17.4 КБ (woff2). Итого ≈ 70 КБ, ≈ 93 КБ в base64.
- **Важно** [замер]: Canvas не ждёт загрузки шрифта и рисует запасным. Если такой текст попадёт в кэш спрайтов (TNT, кнопки), он останется кривым. Поэтому `await loadFonts()` вызывается **до** генерации спрайтов. На `document.fonts.onloadingdone` текстовые спрайты сбрасываются. Если загружать через `document.fonts.load()`, образец обязан содержать и латиницу, и кириллицу (`'АаЁё Aa 0123'`): иначе подгрузится только одно подмножество. В прототипе «Рекорд» нарисовался засечным шрифтом именно из-за этого.
- Для DOM-UI те же семейства задаются в CSS: `font-family: var(--font-ui)`. Обводка текста в DOM — `-webkit-text-stroke` + `paint-order: stroke fill`, тень `0 0.07em 0 rgba(0,0,0,.3)`.

- Следим за `ResizeObserver` и `matchMedia('(resolution: Xdppx)')`: dpr меняется при переносе окна на другой монитор.
- `ctx.imageSmoothingEnabled = true`. При рисовании спрайтов, близких к 1:1, ставим `imageSmoothingQuality = 'low'`, при генерации — `'high'`.

### 10.2. Кэш спрайтов

```ts
export const ppuBucket = (ppu: number) => 2 ** (Math.ceil(4 * Math.log2(ppu)) / 4);  // вверх: спрайт ≥ нужного

export class SpriteCache {
  private map = new Map<string, { s: Sprite; bytes: number }>();   // порядок Map = LRU
  private bytes = 0;
  constructor(private budget = 96 * 2 ** 20) {}
  get(key: string, make: () => Sprite): Sprite {
    const hit = this.map.get(key);
    if (hit) { this.map.delete(key); this.map.set(key, hit); return hit.s; }
    const s = make(), bytes = s.canvas.width * s.canvas.height * 4;
    this.map.set(key, { s, bytes }); this.bytes += bytes;
    for (const [k, v] of this.map) { if (this.bytes <= this.budget) break; if (k === key) continue; this.map.delete(k); this.bytes -= v.bytes; }
    return s;
  }
}
// ключи
blockKey = `blk:${mat}:${shape}:${w.toFixed(2)}x${h.toFixed(2)}:${stage}:${seed & 3}:${bucket}`;
tntKey   = `tnt:${size.toFixed(2)}:${bucket}`;
slingKey = `sling:${part}:${bucket}`;
cloudKey = `cloud:${theme}:${variant}:${bucket}`;
// персонажи — по 02 §5.9
```

- **Бюджет** 96 МБ (desktop) / 48 МБ (mobile). Блок 2×0.5 м при 144 ppu весит 300×86 px ≈ 103 КБ. На уровне с ~15 уникальными блоками × 4 стадии × 2 bucket выходит около 12 МБ.
- **Прогрев** при загрузке уровня: стадия 0 всех уникальных блоков, рогатка, облака, деревья в текущем bucket. Это 15–30 спрайтов по 0.2–0.5 мс — меньше 15 мс, под экраном загрузки.
- **Ленивая генерация** стадий 1–3 — по событию `blockDamaged`. Бюджет генерации — 4 мс за кадр. Если бюджет исчерпан, рисуем спрайт ближайшей готовой стадии или bucket и дорисовываем на следующем кадре.
- **Смена bucket** при зуме: спрайт старого bucket рисуется с масштабом (≤ ×1.19), новые генерируются в рамках того же бюджета 4 мс/кадр, ближние к центру экрана — первыми.

### 10.3. Отрисовка тела

```ts
// Периодический value noise (бесшовный тайл); rng — mulberry32 из src/core/rng.ts
function valueNoise2D(seed: number, period: number) {
  const r = mulberry32(seed), g = new Float32Array(period * period);
  for (let i = 0; i < g.length; i++) g[i] = r();
  return (x: number, y: number) => {
    const xi = Math.floor(x), yi = Math.floor(y), xf = x - xi, yf = y - yi;
    const u = xf * xf * (3 - 2 * xf), v = yf * yf * (3 - 2 * yf);
    const x0 = ((xi % period) + period) % period, y0 = ((yi % period) + period) % period;
    const x1 = (x0 + 1) % period, y1 = (y0 + 1) % period;
    const a = g[y0 * period + x0], b = g[y0 * period + x1], c = g[y1 * period + x0], d = g[y1 * period + x1];
    return a + (b - a) * u + (c - a) * v + (a - b - c + d) * u * v;
  };
}
```

- Тайлы генерируются один раз на тему: грунт 512² — около 15 мс, камень 128² — около 2 мс. Делать это под экраном загрузки.

### 10.5. Тени и свечения

### 11.1. Блок дерева: волокна, сучки, торцы, трещины, сколы

```ts
const WOOD = { light: '#F0C27A', base: '#D08F45', dark: '#9C6030', deep: '#7A4620', outline: '#4A2810',
  grain: '#A9672E', knot: '#7E4A20', crack: '#3A1E0A', crackLight: '#FFE2A8', nail: '#6A6A70' };
const OUT_BLOCK = 0.035;
const CRACKS_BY_STAGE = [0, 1, 3, 6];

export function renderWoodRect(w: number, h: number, stage: number, seed: number, ppu: number): Sprite {
  const pad = OUT_BLOCK + 2 / ppu;
  const c = createCanvas((w + 2 * pad) * ppu, (h + 2 * pad) * ppu), ctx = ctx2d(c);
  ctx.setTransform(ppu, 0, 0, ppu, c.width / 2, c.height / 2);           // метры, Y вниз, 0 — центр
  const rng = mulberry32(seed * 7919 + 13), mn = Math.min(w, h), mx = Math.max(w, h);
  const horiz = w >= h, len = mx, thick = mn;
  const shape = new Path2D(); shape.roundRect(-w / 2, -h / 2, w, h, clamp(0.07 * mn, 0.012, 0.05));

  ctx.save(); ctx.clip(shape);
  const g = ctx.createLinearGradient(0, -h / 2, 0, h / 2);
  g.addColorStop(0, WOOD.light); g.addColorStop(0.35, WOOD.base); g.addColorStop(1, WOOD.dark);
  ctx.fillStyle = g; ctx.fillRect(-w / 2, -h / 2, w, h);

  ctx.save(); if (!horiz) ctx.rotate(Math.PI / 2);                       // дальше длина — по X
  // сучки
  const knots: Array<[number, number]> = [];
  const kn = Math.floor(len / 0.9 * rng() + rng() * 0.8);
  for (let i = 0; i < kn; i++) knots.push([lerp(-len / 2 + 0.15, len / 2 - 0.15, rng()), lerp(-thick / 2 + 0.06, thick / 2 - 0.06, rng())]);
  // волокна: синусоиды, обтекающие сучки
  const n = Math.max(2, Math.round(thick / 0.075));
  ctx.strokeStyle = rgba(WOOD.grain, 0.55); ctx.lineCap = 'round';
  for (let i = 0; i < n; i++) {
    const y0 = -thick / 2 + (i + 0.5) * thick / n + (rng() - 0.5) * thick / n * 0.4;
    const lam = lerp(0.6, 1.3, rng()), ph = rng() * TAU;
    ctx.lineWidth = lerp(0.008, 0.016, rng());
    ctx.beginPath();
    for (let x = -len / 2; x <= len / 2 + 1e-3; x += 0.04) {
      let y = y0 + 0.012 * Math.sin(TAU * x / lam + ph);
      for (const [kx, ky] of knots) {
        const d = x - kx;
        y += (y0 > ky ? 1 : -1) * 0.035 * Math.exp(-d * d / 0.01) * Math.exp(-Math.abs(y0 - ky) / 0.08);
      }
      x === -len / 2 ? ctx.moveTo(x, y) : ctx.lineTo(x, y);
    }
    ctx.stroke();
  }
  for (const [kx, ky] of knots) {
    ctx.fillStyle = WOOD.knot; ctx.beginPath(); ctx.ellipse(kx, ky, 0.05, 0.025, 0, 0, TAU); ctx.fill();
    ctx.strokeStyle = rgba(WOOD.grain, 0.7); ctx.lineWidth = 0.008;
    ctx.beginPath(); ctx.ellipse(kx, ky, 0.075, 0.04, 0, 0, TAU); ctx.stroke();
  }
  // торцы: затемнение + гвозди
  if (len / thick > 2.2) for (const s of [-1, 1]) {
    const eg = ctx.createLinearGradient(s * len / 2, 0, s * (len / 2 - 0.12), 0);
    eg.addColorStop(0, rgba(WOOD.deep, 0.45)); eg.addColorStop(1, rgba(WOOD.deep, 0));
    ctx.fillStyle = eg; ctx.fillRect(s > 0 ? len / 2 - 0.12 : -len / 2, -thick / 2, 0.12, thick);
    const nr = clamp(thick * 0.07, 0.012, 0.022);
    for (const ny of thick > 0.3 ? [-0.25, 0.25] : [0]) {
      const nx = s * (len / 2 - 0.09), yy = ny * thick;
      ctx.fillStyle = WOOD.deep; ctx.beginPath(); ctx.arc(nx + nr * 0.25, yy + nr * 0.25, nr * 1.1, 0, TAU); ctx.fill();
      ctx.fillStyle = WOOD.nail; ctx.beginPath(); ctx.arc(nx, yy, nr, 0, TAU); ctx.fill();
      ctx.fillStyle = 'rgba(255,255,255,0.6)'; ctx.beginPath(); ctx.arc(nx - nr * 0.3, yy - nr * 0.3, nr * 0.35, 0, TAU); ctx.fill();
    }
  }
  ctx.restore();
  // ящик (квадраты) или швы досок (широкие) — §7.3 п.5–6, опущено для краткости
  bevel(ctx, w, h, clamp(0.16 * mn, 0.025, 0.07), WOOD.light, WOOD.deep, 0.75, 0.55);
  ctx.restore();

  const lw = Math.max(OUT_BLOCK, 1.5 / ppu);
  ctx.lineJoin = 'round'; ctx.lineWidth = lw; ctx.strokeStyle = WOOD.outline; ctx.stroke(shape);

  if (stage > 0) {                                                       // трещины копятся по стадиям
    const crng = mulberry32(seed * 31 + 7);
    const cracks = genCracks(crng, w, h, 6, 0.07, 0.35, 0.25);            // [{pts, main, widthK}]
    const wMain = clamp(0.045 * mn + 0.012, 0.016, 0.034);
    ctx.save(); ctx.clip(shape);
    for (const cr of cracks) if (cr.main < CRACKS_BY_STAGE[stage])
      strokeCrack(ctx, cr.pts, wMain * cr.widthK, WOOD.crack, rgba(WOOD.crackLight, 0.7), wMain * 0.45);
    ctx.restore();
    if (stage >= 2) for (let i = 0; i < stage - 1; i++)                   // 1 угол на стадии 2, 2 — на стадии 3
      chipCorner(ctx, w, h, mulberry32(seed * 101 + i * 977), Math.floor(mulberry32(seed * 101 + (9 + i) * 977)() * 4),
                 clamp(0.22 * mn, 0.04, 0.16) * (stage === 3 ? 1.3 : 0.8), WOOD.outline, lw, shape);
  }
  return { canvas: c, ox: c.width / 2, oy: c.height / 2, ppu };
}

function strokeCrack(ctx: Ctx2D, pts: Array<[number, number]>, wd: number, dark: string, light: string, off: number) {
  ctx.lineCap = 'round'; ctx.lineJoin = 'round';
  ctx.strokeStyle = light; ctx.lineWidth = wd * 0.55;                    // освещённая стенка щели (вниз-вправо)
  ctx.beginPath(); pts.forEach(([x, y], i) => (i ? ctx.lineTo(x + off, y + off) : ctx.moveTo(x + off, y + off))); ctx.stroke();
  ctx.strokeStyle = dark;                                                 // щель сужается к концу
  for (let i = 1; i < pts.length; i++) {
    ctx.lineWidth = wd * lerp(1, 0.35, i / pts.length);
    ctx.beginPath(); ctx.moveTo(pts[i - 1][0], pts[i - 1][1]); ctx.lineTo(pts[i][0], pts[i][1]); ctx.stroke();
  }
}

function chipCorner(ctx: Ctx2D, w: number, h: number, rng: () => number, corner: number, size: number,
                    outline: string, lw: number, shape: Path2D) {
  const sx = corner & 1 ? 1 : -1, sy = corner & 2 ? 1 : -1, cx = sx * w / 2, cy = sy * h / 2;
  const a = size * lerp(0.7, 1.2, rng()), b = size * lerp(0.7, 1.2, rng());
  const p = new Path2D();
  p.moveTo(cx - sx * a, cy + sy * 0.02); p.lineTo(cx - sx * a * 0.55, cy - sy * b * 0.35);
  p.lineTo(cx - sx * a * 0.2, cy - sy * b * 0.55); p.lineTo(cx + sx * 0.02, cy - sy * b);
  p.lineTo(cx + sx * 0.05, cy + sy * 0.05); p.closePath();
  ctx.save(); ctx.clip(shape); ctx.strokeStyle = outline; ctx.lineWidth = lw * 2; ctx.lineJoin = 'round'; ctx.stroke(p); ctx.restore();
  ctx.save(); ctx.globalCompositeOperation = 'destination-out'; ctx.fill(p); ctx.restore();
}
```

### 11.2. Облако

```ts
export function renderCloud(seed: number, widthM: number, ppm: number, C: { top: string; bottom: string }): Sprite {
  const rng = mulberry32(seed), w = widthM, h = w * 0.42, base = h * 0.78;
  const c = createCanvas((w + 0.4) * ppm, (h + 0.7) * ppm), ctx = ctx2d(c);
  ctx.setTransform(ppm, 0, 0, ppm, 0.2 * ppm, 0.5 * ppm);                 // метры, Y вниз; запас сверху 0.5 м
  const blobs: Array<[number, number, number]> = [];
  const n = 5 + Math.floor(rng() * 3);
  for (let i = 0; i < n; i++) {
    const t = (i + 0.5) / n, x = w * (0.12 + 0.76 * t);
    const r = h * (0.28 + 0.34 * Math.sin(Math.PI * t)) * lerp(0.85, 1.15, rng());
    blobs.push([x, base - r * 0.55, r]);
  }
  const body = new Path2D();
  for (const [x, y, r] of blobs) { body.moveTo(x + r, y); body.arc(x, y, r, 0, TAU); }
  body.rect(w * 0.1, base - h * 0.25, w * 0.8, h * 0.25);
  ctx.save();
  ctx.beginPath(); ctx.rect(-1, -1, w + 2, base + 1); ctx.clip();         // плоское дно (rect: y=-1, высота base+1!)
  const g = ctx.createLinearGradient(0, 0, 0, base);
  g.addColorStop(0, C.top); g.addColorStop(0.55, C.top); g.addColorStop(1, C.bottom);
  ctx.fillStyle = g; ctx.fill(body);
  ctx.clip(body);
  ctx.fillStyle = rgba(C.bottom, 0.55);                                   // подбрюшье
  for (const [x, y, r] of blobs) { ctx.beginPath(); ctx.arc(x + r * 0.25, y + r * 0.45, r * 0.8, 0, TAU); ctx.fill(); }
  ctx.fillStyle = 'rgba(255,255,255,0.55)';                               // блики сверху-слева
  for (const [x, y, r] of blobs) { ctx.beginPath(); ctx.arc(x - r * 0.3, y - r * 0.35, r * 0.45, 0, TAU); ctx.fill(); }
  ctx.restore();
  return { canvas: c, ox: 0.2 * ppm, oy: (0.5 + base) * ppm, ppu: ppm };  // якорь — левый край дна
}
```

Баг, пойманный в прототипе: `rect(-1, -1, w + 2, base)` срезает облако на 1 м выше дна, получается тонкая полоска. Нужна высота `base + 1`.

### 11.3. Слой холмов (полоса)

```ts
interface HillLayer { id: string; f: number; period: number; baseY: number; height: number; depth: number; res: number;
  terms: Array<[k: number, a: number]>; amp0: number; near: boolean; decoDensity: number; decoScale: number; trees: boolean; seed: number }

export function buildHillStrip(L: HillLayer, pal: ThemePalette, ppm: number): HTMLCanvasElement {
  const C = L.near ? pal.hillsNear : pal.hillsFar, P = L.period, rng = mulberry32(L.seed);
  const c = createCanvas(P * ppm, (L.height + L.depth) * ppm), ctx = ctx2d(c);
  ctx.setTransform(ppm, 0, 0, -ppm, 0, L.height * ppm);                   // метры слоя, Y вверх, 0 — база
  const ph = L.terms.map(() => rng() * TAU);
  const H = (x: number) => L.amp0 + L.terms.reduce((s, [k, a], i) => s + a * Math.sin(TAU * k * x / P + ph[i]), 0);
  const N = Math.ceil(P * 5);
  const ridge = new Path2D(); ridge.moveTo(0, -L.depth);
  for (let i = 0; i <= N; i++) ridge.lineTo(i / N * P, H(i / N * P));
  ridge.lineTo(P, -L.depth); ridge.closePath();
  const g = ctx.createLinearGradient(0, L.height, 0, -L.depth);
  g.addColorStop(0, C.top); g.addColorStop(1, C.bottom);
  ctx.fillStyle = g; ctx.fill(ridge);
  ctx.save(); ctx.clip(ridge);
  ctx.beginPath();                                                         // светлый «рим» по гребню
  for (let i = 0; i <= N; i++) { const x = i / N * P; i ? ctx.lineTo(x, H(x) - 0.07) : ctx.moveTo(x, H(x) - 0.07); }
  ctx.lineWidth = 0.16; ctx.strokeStyle = rgba(C.rim, 0.85); ctx.stroke();
  const count = Math.round(P * L.decoDensity);                             // кусты/деревца, с переносом через край тайла
  for (let i = 0; i < count; i++) {
    const x = rng() * P, y = H(x) - 0.05, r = lerp(0.25, 0.55, rng()) * L.decoScale, tree = L.trees && rng() < 0.45;
    for (const dx of [0, P, -P]) {
      const X = x + dx; if (X < -1 || X > P + 1) continue;
      ctx.fillStyle = C.deco;
      if (tree) {
        ctx.fillRect(X - r * 0.12, y, r * 0.24, r * 1.2);
        ctx.beginPath(); ctx.arc(X, y + r * 1.6, r * 0.75, 0, TAU); ctx.fill();
        ctx.fillStyle = rgba(C.decoLight, 0.8); ctx.beginPath(); ctx.arc(X - r * 0.2, y + r * 1.8, r * 0.38, 0, TAU); ctx.fill();
      } else {
        ctx.beginPath();
        ctx.arc(X - r * 0.6, y + r * 0.25, r * 0.55, 0, TAU); ctx.arc(X, y + r * 0.45, r * 0.7, 0, TAU); ctx.arc(X + r * 0.6, y + r * 0.2, r * 0.5, 0, TAU);
        ctx.fill();
        ctx.fillStyle = rgba(C.decoLight, 0.75); ctx.beginPath(); ctx.arc(X - r * 0.15, y + r * 0.7, r * 0.32, 0, TAU); ctx.fill();
      }
    }
  }
  const fog = ctx.createLinearGradient(0, L.amp0, 0, -L.depth);           // атмосферная дымка книзу
  fog.addColorStop(0, rgba(pal.fog, 0)); fog.addColorStop(1, rgba(pal.fog, L.near ? 0.12 : 0.3));
  ctx.fillStyle = fog; ctx.fillRect(0, -L.depth, P, L.amp0 + L.depth);
  ctx.restore();
  return c;
}

export function drawLayer(ctx: Ctx2D, v: ViewInfo, L: HillLayer, strip: { c: HTMLCanvasElement; ppm: number }, fillBelow: string) {
  const sRef = v.screenH / 15, sL = sRef * Math.pow(v.scale / sRef, L.f), k = sL / strip.ppm;
  const wPx = strip.c.width * k, hPx = strip.c.height * k;
  let x0 = v.screenW / 2 - v.camX * L.f * sL; x0 = ((x0 % wPx) + wPx) % wPx - wPx;
  const yTop = v.screenH / 2 - (L.baseY - v.camY * L.f) * sL - L.height * sL;
  ctx.setTransform(1, 0, 0, 1, 0, 0);
  for (let x = x0; x < v.screenW; x += wPx) ctx.drawImage(strip.c, x, yTop, wPx + 0.5, hPx);
  const yB = yTop + hPx - 1;
  if (yB < v.screenH) { ctx.fillStyle = fillBelow; ctx.fillRect(0, yB, v.screenW, v.screenH - yB); }
}
```

### 11.4. Вспышка взрыва (огненный шар, волна, искры)

```ts
export function drawExplosion(ctx: Ctx2D, v: ViewInfo, x: number, y: number, R: number, t: number, seed: number) {
  const rng = mulberry32(seed);
  applyWorldTransform(ctx, v); ctx.translate(x, y);                       // метры, Y вверх
  if (t < 0.12) {                                                          // 1) вспышка
    const a = 1 - t / 0.12, r = R * lerp(0.6, 1.3, t / 0.12);
    const g = ctx.createRadialGradient(0, 0, 0, 0, 0, r);
    g.addColorStop(0, `rgba(255,255,240,${a})`); g.addColorStop(0.4, `rgba(255,230,140,${a * 0.8})`); g.addColorStop(1, 'rgba(255,160,40,0)');
    ctx.globalCompositeOperation = 'lighter'; ctx.fillStyle = g;
    ctx.beginPath(); ctx.arc(0, 0, r, 0, TAU); ctx.fill();
    ctx.globalCompositeOperation = 'source-over';
  }
  if (t < 0.3) {                                                           // 2) ударная волна
    const k = easeOutCubic(t / 0.3);
    ctx.strokeStyle = `rgba(255,255,255,${0.85 * (1 - k)})`; ctx.lineWidth = lerp(0.28, 0.04, k) * R;
    ctx.beginPath(); ctx.arc(0, 0, lerp(0.2, 1.6, k) * R, 0, TAU); ctx.stroke();
  }
  for (let i = 0; i < 9; i++) {                                            // 3) огненный шар → дым
    const ang = i / 9 * TAU + rng() * 0.5, d = R * lerp(0.15, 0.55, rng()), r0 = R * lerp(0.28, 0.45, rng());
    const tt = t - rng() * 0.05; if (tt <= 0) continue;
    const grow = easeOutCubic(Math.min(1, tt / 0.2));
    const px = Math.cos(ang) * d * (0.4 + 0.8 * grow), py = Math.sin(ang) * d * (0.4 + 0.8 * grow) + tt * 0.9;
    const r = r0 * (0.4 + 0.8 * grow) * (1 + tt * 0.5);
    const heat = clamp(1 - (tt - 0.06) / 0.25, 0, 1), alpha = clamp(1 - (tt - 0.35) / 0.4, 0, 1);
    if (alpha <= 0) continue;
    const core = mixHex('#A8A2AA', '#FFD04A', heat), edge = mixHex('#77707C', '#FF7A1A', heat);
    const g = ctx.createRadialGradient(px - r * 0.3, py + r * 0.3, r * 0.1, px, py, r);  // свет сверху-слева (Y вверх)
    g.addColorStop(0, rgba(heat > 0.5 ? '#FFF6C0' : core, alpha)); g.addColorStop(0.5, rgba(core, alpha)); g.addColorStop(1, rgba(edge, alpha * 0.9));
    ctx.fillStyle = g; ctx.beginPath(); ctx.arc(px, py, r, 0, TAU); ctx.fill();
  }
  if (t < 0.4) {                                                           // 4) искры
    ctx.globalCompositeOperation = 'lighter'; ctx.lineCap = 'round';
    ctx.strokeStyle = `rgba(255,226,122,${1 - t / 0.4})`; ctx.lineWidth = 0.06 * R;
    ctx.beginPath();
    for (let i = 0; i < 14; i++) {
      const a = rng() * TAU, sp = R * lerp(5, 9, rng()), d0 = sp * t, d1 = sp * Math.max(0, t - 0.04), sag = 3 * t * t;
      ctx.moveTo(Math.cos(a) * d1, Math.sin(a) * d1 - sag); ctx.lineTo(Math.cos(a) * d0, Math.sin(a) * d0 - sag);
    }
    ctx.stroke(); ctx.globalCompositeOperation = 'source-over';
  }
}
```

`seed` фиксируется на событие (например, id + время), чтобы раскладка пуфов не прыгала между кадрами. 9 радиальных градиентов на взрыв в кадре — дёшево: 100 градиентов ≈ 0.06 мс [замер].

## 12. Рогатка

Геометрия — 01 §2.1 (основание `S`, `ANCHOR (0, 2.70)`, рога `(−0.30, 2.95)` / `(+0.28, 2.90)`). Две части в кэше: `back` (ствол + задний рог) и `front` (передний рог), плюс точки крепления.

| Элемент | Геометрия (м, от S, Y вверх) | Ширина, м |
|---|---|---|
| Ствол | (0, −0.4) → (0.02, 0.5) → (0, 1.05) → (0, 1.35) | 0.44 → 0.36 |
| Задний рог | (0.02, 1.2) → (−0.2, 1.6) → (−0.32, 2.15) → (−0.30, 2.98) | 0.32 → 0.22, кончик скруглён |
| Передний рог | (−0.02, 1.2) → (0.2, 1.6) → (0.31, 2.15) → (0.28, 2.93) | 0.32 → 0.22 |
| Обмотка у кончика | центр (−0.29, 2.80) / (0.27, 2.75), roundRect 0.30×0.22 r 0.05, наклон −0.08 / +0.10 рад | 3 косые полосы |

| Цвет | Hex |
|---|---|
| Дерево: light / base / dark / outline | `#CB8645` / `#9A5A2A` / `#6A3816` / `#2E190A` |
| Обмотка / полосы | `#5C3A22` / `#8A5E3A` |
| Резинка / блик (01 §2.5) | `#3B2414` / `#6A4528` (ширина 0.3w, сдвиг 0.18w вверх) |
| Ложе: тень → тело / шов | `#4A311C` → `#6B4A2E` / `#D8B88A` (пунктир 0.06/0.05, 0.02) |

Рецепт ветки:
- полоса по ломаной с линейным сужением, на конце полукруг;
- обводка `outline` 0.09 м — рисуется **первой**, заливка поверх оставляет видимые 0.045;
- горизонтальный градиент `light` (слева) → `base` (0.45) → `dark` (справа);
- кора: 9 коротких квадратичных штрихов через 0.32 м по высоте, `dark` α 0.6, 0.025.

Ложе — полумесяц вокруг птицы со стороны, обратной выстрелу. В системе, где +X — направление к `ANCHOR`:
`arc(0, 0, 1.12r, π − 1.05, π + 1.05)`, затем обратно `arc(0.18r, 0, 0.86r, π + 0.95, π − 0.95, ccw)`.
Обводка 0.05, шов — дуга радиуса 1.0r. Кончики полумесяца лежат в `pocket ± perp·0.38 − dir·0.24`, туда и крепятся резинки (совпадает с 01 §2.5).

Порядок — §2: back до рельефа; задняя резинка → птица → ложе → передняя резинка → front.

## 13. Чек-лист приёмки визуала

Скриншоты — через `scripts/shot.mjs`. Эталоны — `04-visual-*.jpg`.

1. Каждая тема в виде рогатки (viewH 15) и на общем плане (viewH = fit) без исключений в консоли. Нет щелей между копиями тайлов: столбец пикселей на стыке не отличается от соседних больше чем на 8/255.
2. При панорамировании и зуме дальние слои движутся медленнее ближних. При `f = 0.12` и отъезде 15 → 42 м масштаб гор меняется не больше чем на 15 %.
3. Лист материалов: 3 материала × {rect, circle, triangle, isoTriangle} × стадии 0–3 рендерятся. Трещины стадии n содержат все трещины стадии n−1 — тест сравнивает пиксели внутри трещин.
4. Скол не выходит за силуэт: альфа пикселей вне формы блока = 0.
5. `document.fonts.check('900 20px Rubik', 'Ёё')` и `check('400 20px "Luckiest Guy"', '0')` → true до первой генерации спрайтов.
6. В коде кадра нет `shadowBlur`: grep-тест по `src/render/**` за пределами `sprites/`.
7. Число частиц никогда не превышает лимит ступени; всплывающие очки при переполнении не теряются (юнит-тест `Fx`).
8. Ночная тема: очки и вспышки рисуются после тонировки (их пиксели ярче, чем при тонировке).
9. Производительность на эталонной сцене (40 блоков, 3 свиньи, взрыв + 300 частиц, 1920×1080, dpr 2): медиана кадра ≤ 16.7 мс, 99-й перцентиль ≤ 25 мс. Проверка в браузере с GPU-канвасом.
